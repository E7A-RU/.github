# E7A — инженерная философия

**Статус: концептуально согласовано владельцем 25.10.2026; распространение в main ещё требует review Draft PR.**

> E7A — экосистема самостоятельных цифровых продуктов, объединённых **единой идентичностью зарегистрированных субъектов**, общим версионированным инженерным фундаментом, воспроизводимыми правилами качества, контролируемыми релизами и управляемой инфраструктурой.

## Неподвижные принципы

1. **Person-first, privacy-by-design.** Единая Identity для зарегистрированных разработчиков, администраторов, пользователей, организаций и service accounts. Быть «известным E7A» не равно доказанной юридической личности; подтверждения имеют источник, срок, уровень доверия и разрешённую область раскрытия.
2. **Product-owned domain.** Каждый продукт владеет своей бизнес-логикой, данными, доменной авторизацией, миграциями, worker-процессами при необходимости, релизом и восстановлением. Никакой прямой записи в чужую БД.
3. **Optional runtime dependencies.** Публичный Website и local-first Reader могут работать без логина и общего backend. Зарегистрированные субъекты используют E7A Identity. Platform capabilities подключаются только при реальной потребности.
4. **Core is libraries, not a server.** Брендовые токены/React UI, переносимые типы, contracts, опциональный Starter; версионированные immutable пакеты и независимое принятие продуктов.
5. **Laboratory is a product factory.** Wizard, QA, эксперименты, совместимость и Release Gate; не общая БД/пул чужой бизнес-логики.
6. **Infra is the operator.** Серверы/ВМ, networks, DNS/TLS, provisioning, runners, storage, backup, telemetry и контролируемый rollback. Физическая инфраструктура не является владельцем данных.
7. **Platform is capability-oriented.** Возможные Shared Delivery / Jobs / Connectors / Results для маленьких и больших продуктов; никаких обязательных gateway-hops или богоподобного backend-монолита.
8. **Promises are measurable.** «Accepted», «Delivered» и «Processed» — разные подтверждения; at-least-once, идемпотентность и состояние неопределённости честнее недоказуемого exactly-once.
9. **Humans authorize production.** Автоматизация помогает валидировать/планировать; по умолчанию не меняет production без явного owner approval.
10. **One organization standard.** Канонические правила — здесь, а не семь расходящихся копий. Каждая потребляющая версия стандарта и контрактов известна по ссылке/SHA.
11. **Security before convenience.** Минимальные полномочия, разделение tenants, контроль внешних интеграций, секреты не в Git, ограничение ресурсов и проверяемый off-host backup.
12. **Discover before deploy.** Website предоставляет понятную публичную витрину для B2B/B2C, Laboratory — защищённый вход для команды/партнёров и инженерное производство, а Demo показывает возможности на синтетических данных без обещания готового production. Позиционирование и первые сегменты пока проходят проверку, а не считаются утверждёнными маркетинговыми фактами.
13. **Brand and code rights are separate.** Публичный @e7a-ru/ui@0.2.1 указан как UNLICENSED (internal-first/external-ready); официальные материалы E7A требуют разрешения правообладателей согласно [Brand Policy](../BRAND_POLICY.md). Публичность npm не означает open-source лицензию.

## Из чего состоит экосистема

- **Core:** инженерный фундамент.
- **Laboratory:** создание, испытания и допуск продуктов.
- **Infra:** физическая и виртуальная эксплуатационная платформа.
- **Identity:** центральный каталог субъектов и доверия (самостоятельный будущий продукт).
- **Platform:** общие backend-сервисы по контракту, начиная с проекта СГДС (будущий runtime).
- **Продукты:** Website, Bot Studio, Reader, Planner и новые самостоятельные решения.

**Не смешивать:** «общие стандарты» ≠ «одна база»; «единый логин» ≠ «единые продуктовые роли»; «создать Kit» ≠ «автоматически деплоить»; «доставить сообщение» ≠ «выполнить внешнее действие».
