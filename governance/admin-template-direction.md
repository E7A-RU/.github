# E7A Admin Template — единый необязательный шаблон административных интерфейсов

**Статус: OWNER-DIRECTED PRODUCT / PRIVATE REPOSITORY BOOTSTRAPPED (2026-11-05).**
Владелец выделил E7A Admin Template в самостоятельный продукт-шаблон и создал приватный [`E7A-RU/admin-template`](https://github.com/E7A-RU/admin-template). **Документационный bootstrap принят в [PR #1](https://github.com/E7A-RU/admin-template/pull/1), `main@d56031adea734f3ae2da4942ae43f78f5b8be068`.** Приняты README, AGENTS, Governance 2.0.0 consumer pin, Charter, Roadmap, Maintainership и security/acceptance boundaries. **Приложение, исполняемый QA, публикация пакета, runtime, публичная лицензия и production не подтверждены.** Эта запись не меняет опубликованный Governance 2.0.0 и не даёт deployment authorization.

## Зачем это E7A

Чтобы при росте E7A повторно использовать хорошо проверенные решения для кабинетов, внутренних операторских панелей, B2B-продуктов и управления конкретными продуктами — без копирования несогласованных навигации, таблиц, форм и оформлений.

**Предлагаемый продуктовый принцип:** «Сложное понятно» — ясные подписи, понятные состояния и последствия действий, внимание к доступности, а не только красивый dashboard.

## Архитектурное место и границы

- **E7A Admin Template** — отдельный независимый **продукт-шаблон**, [приватный репозиторий `E7A-RU/admin-template`](https://github.com/E7A-RU/admin-template) инициализирован, README/AGENTS/Charter/QA-границы приняты документационным PR. Его будущие приложение, QA, версии пакетов и релизы остаются продуктовой ответственностью; пока это **BOOTSTRAPPED / AT0 PENDING**, а не реализованная UI-библиотека или работающий сервис.
- **E7A Core** остаётся единственным владельцем общих UI-компонентов, токенов, дизайн-системы и опционального Product Starter. Admin Template потребляет **точную опубликованную версию** Core UI, не копирует core tokens/компоненты; позже может подключаться к Starter как необязательный профиль/источник пресета по отдельному проверенному контракту. Core и Admin Template имеют независимые версии.
- **Три Product Kit остаются неизменными:** Browser-only, Full-stack, Service/Worker. Admin Template — **слой интерфейса**, а не четвёртый Kit, новый общий backend, обязательный портал или управляющая платформа.
- **Каждый продукт** владеет своими реальными API, данными, ролями, аудитом, бизнес-логикой и релизами. Шаблон предоставляет компоненты и примеры, но **не выдаёт прав доступа**, не переносит чужие базы и не предопределяет shared backend.
- **Identity** при необходимости обеспечивает аутентификацию/доверие, но реальный backend обязан самостоятельно проверять authorization. Скрытие кнопки в UI **не считается access control**.
- **Infra** отвечает за приватную эксплуатацию/секреты/ресурсы; **Laboratory** в будущем может предлагать Admin Template как опциональный выбор при создании продукта; **Website** показывает только честно выпущенные возможности и ссылки.

## Два направления применения

| Направление | Пример | Обязательные ограничения |
| --- | --- | --- |
| **Внутреннее E7A** | приватный read-only кабинет наблюдаемости, support/операционная панель, инструменты Laboratory | private access, least privilege, no raw Docker socket/secrets in UI; первые примеры — только synthetic или read-only data |
| **Публичное / клиентское** | панель управления самостоятельным продуктом, B2B рабочее пространство, версия Starter для внешней команды | независимое владение данными, собственная серверная authZ, privacy/security review, маркировка демо, отдельные условия лицензии и брендирования |

**Публично используемый шаблон ≠ публичная административная панель E7A Infra.** Реальные внутренние endpoints, токены и operator controls никогда не становятся частью публичной поставки.

## Предлагаемый состав MVP

- **Оболочка:** responsive sidebar/topbar, breadcrumbs, search/navigation, keyboard shortcuts по потребности.
- **Плотные рабочие интерфейсы:** таблицы, сортировка/фильтрация, списки, карточки деталей, формы, валидация, bulk-действия с понятным подтверждением.
- **Состояния:** loading/empty/error/permission denied/partial data/UNKNOWN, last-updated и источник данных; никакой выдуманной доступности или аналитических процентов.
- **Визуальная система:** переиспользование E7A Core UI, светлая и тёмная темы, responsive/mobile, RU/EN, WCAG/клавиатура/reduced motion.
- **Примеры:** только синтетические данные, mock API boundaries, отсутствие реальных секретов, платежей, пользователей и production-side-effects.
- **Расширяемость:** конфигурируемая навигация и композиция без обязательного общего auth SDK, БД, очереди, аналитики, провайдера или SaaS.

## Этапы и критерии перехода

| Этап | Цель | Gate |
| --- | --- | --- |
| **AT0 — Discovery** | Сопоставить реальные задачи внутренних кабинетов и одного внешнего B2B сценария; решить, каких компонентов ещё нет в Core | 2–3 проверенных сценария, UX/brand/permission boundaries, выбор владельца |
| **AT1 — UI specification & preview** | Read-only прототип оболочки и 4–6 ключевых паттернов с synthetic data, RU/EN, dark/light, mobile | UX/a11y/visual acceptance, угрозы spoofed admin UI, no backend claims |
| **AT2 — Independent Admin Template MVP** | В приватном `E7A-RU/admin-template` разработать версионируемый исходный шаблон, воспроизводимый scaffold и тестовый consumer; последующая опциональная интеграция с Core Starter — отдельная задача | exact-SHA self-hosted QA, frozen install, TypeScript, browser/a11y, независимые версии и отсутствие обязательного общего backend |
| **AT3 — Internal pilot** | Принять профиль в одном безопасном внутреннем кабинете, предпочтительно read-only | отдельный product/Infra PR, реальные роли/доступ, privacy, health/rollback, owner authorization |
| **AT4 — Public distribution decision** | Отдельно решить пакет/шаблон, документацию и модель распространения | code license, brand rights, security review, support/versioning, independently tested clean install; отдельное разрешение на публикацию |

Этапы не имеют утверждённых сроков и **не являются утверждением текущей реализации**. Начинать AT2 до AT0/AT1 только после отдельного owner-reviewed scope.

## Правила безопасности и масштабирования

1. Ни default admin account, ни общие пароли, ни встроенные токены, ни доступ к Infra/Platform/Identity на основании одного шаблона.
2. Примеры серверных данных и «продукт готов» не выдавать за работающий backend; auth, tenant isolation, API security, аудит и восстановление тестируются **в каждом реальном consumer**.
3. **Core UI 0.3.0 публично доступен, но помечен `UNLICENSED`**; публичное распространение собственного Admin Template, право третьих лиц изменять код, официальная символика E7A и торговая марка требуют отдельных юридических/лицензионных решений. Нельзя автоматически назвать продукт open source.
4. Версионирование профиля должно быть отделено от версий конкретных продуктов и production-сервисов. Никаких каскадных обновлений после выпуска Core.
5. GitHub-hosted Actions CI запрещён. Проверки — local/self-hosted exact-SHA. Создание template не включает деплой, дополнительные VM, обязательный staging или новые привилегии.
6. Не создавать новый репозиторий/пакет только ради названия до утверждения границ, лицензии и первого сценария.

- Лицензия кода, визуальные права, режим брендирования/white-label для внешних пользователей.
- Требования к доступности, мобильному интерфейсу, локализации, поддержке и безопасности конкретного pilot-продукта.
