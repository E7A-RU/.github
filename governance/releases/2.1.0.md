## New requirements: who owns updates

1. **Core:** produces and reviews independently versioned immutable public `@e7a-ru/ui` and private `@e7a-ru/server` SDKs; maintains *optional* Starter defaults. Published packages do not depend on a product's Next.js release cycle.
2. **Each consuming product:** independently selects exact direct published runtime/framework versions, installs with a genuine frozen lockfile, performs risk-appropriate source/visual/integration/security QA, and separately authorizes release/rollback. A Core Starter Next.js security patch does **not** update an existing product.
3. **Automation:** read-only inventory and bounded reviewable impact suggestions/handoffs, not autonomous product writes, GitHub App activation, auto-merge, auto-deploy, credentials or cross-product dependency bumps.
4. **Exceptions:** library peerDependency compatibility ranges, controlled dev tooling, and narrowly scoped time-bounded Owner-approved ADRs; do not force exact semver on transitive lockfile entries by hand.
5. **Security:** product owners act on their own affected dependencies promptly; Core separately updates SDKs and future Starter defaults. No blanket lockstep framework upgrade.

## Impacted consumers and migration

**Affected scope:** `core`, `website`, `reader`, `bot`, `planner`, `infra`, `laboratory`, `gateway`, `identity`, `platform`, `automation`, `admin-template` plus future E7A products. Exact application depends on product Kit and installed packages; an absent optional Server/UI dependency does not need to be introduced.

**New products:** follow the approved 2.1.0 policy from initial bootstrap. **Existing products:** at next dependency/security change or already approved product PR, document exact current framework/Core packages/lockfile, assess compatibility, update the product's own `governance-consumer.json` pointer through a reviewed PR and run applicable exact-SHA gates. Urgent advisories are triaged promptly, not deferred for a synchronized Core rollout. Historic `v1.1.0`/`v2.0.0` pins remain factual state until that per-product PR lands.

**Core implementation:** [Core PR #44](https://github.com/E7A-RU/core/pull/44) separately proposes the new Starter default Next.js 16.4.5 and Core-local policy; initial exact-head test evidence 65/65 PASS on Lobachevsky at `96e07052318c912c6b92128c9bd91a85a0935fe3`, but Core governance-consumer pin 2.1.0 adoption is a **separate proof/PR** and not a result of this Governance descriptor.

**No automatic side effects:** do not create or install GitHub Apps, auto-write product dependencies, register GitHub-hosted Actions CI, merge product PRs, publish UI/Server again or deploy. Existing published UI 0.3.0 integrity and private Server 0.1.0 remain their own evidence; Server 0.2.0 source-only.
