# Governance 3.0.0 — central authorization authority

**Release class: MAJOR / BREAKING policy boundary.** Owner Decision 064 (2026-11-10) approves the architectural content and release classification. **This source document is not an immutable release descriptor.** It becomes normative only when a *separate reviewed publication* updates `governance/standards-release.json` to 3.0.0 with exact accepted governance source SHA. Until that point, published 2.1.0 is normative.

## What changes

- E7A Identity becomes the **canonical control plane** for ecosystem grants and permission schema approval, Product Trust Registry, Person, Organizations, Workspaces, active entitlements, bounded Product Installations, cross-organization technical grants, policy templates and resource relation decisions.
- Products continue to own their business domain data and databases, resource lifecycle and truth of resource existence, domain invariants, own API enforcement/PEP, independent versioned release and recovery. Their existing ACLs remain until an explicitly approved, reversible transition. Central authorization does **not** imply one global database, a shared API gateway or a synchronous dependency of anonymous products.
- Identity initially selects **ZITADEL + OpenFGA** within its own independently governed implementation; deployment requires licensing/security/Infra acceptance and measured PoC. Other products need not run these components.
- Each Product Installation has one owning Organization and may cover multiple explicitly approved Workspaces of that Organization. Multiple installations of one Product are isolated; cross-Organization sharing is explicit, scoped and revocable.
- Access is constrained by Product Trust, approved product schema, Organization Entitlement, Installation `workspace_scope`, delegated role/grant and policy risk/assurance conditions. Technical product owners/СТП may be external to owning organizations, with limited grants.
- Policy Templates are versioned; managed inheritance and independent fork are allowed without copying other organizations' members, grants or secrets.
- Protected critical operations require fresh checks; R0 anonymous/offline independent, R1 signed scoped lease up to 30 seconds only when revocation freshness is confirmed, R2/R3 online/fail-closed. Targets of 5/15 seconds remain *unmeasured goals* until PoC acceptance.

## Unchanged safeguards

- Protected GitHub PR review, Owner/security/Infra role separation, exact-SHA self-hosted/local QA, immutable artifacts, product-scoped standing authorization for eligible low-risk code only, explicit R2+ approvals, risk-triggered staging, independent backups/restore, rollback and incident operations.
- GitHub-hosted Actions CI prohibited; Core publishing exception remains narrow. No auto-merge/auto-deploy or broad automation write scope from Governance publication.
- Independent Core versioned packages and optional Starter; E7A Design System for Identity UI; Website/Reader anonymous/local use preserved; no forced user signup; no secret or PII in Governance.
- Central Audit/Billing/Platform remain separate services and domains; no bootstrap dependency cycles and no fake runtime readiness.

## Known non-blocking implementation questions (must be resolved before deployment)

- ZITADEL organization federation/linking design and license/support; OpenFGA store/model compilation and consistency.
- Anonymous availability vs revocation freshness, idempotent product-resource registration, installation-scope overlap, authorization audit/provenance, resilience RPO/RTO, KYC/KYB evidence custody and retention.
- Infrastructure admission, secret/key handling, breaks in local tenant ACL migration, and exception handling for privileges and emergency access.

**Source-merge permission is not production or implementation admission.**
